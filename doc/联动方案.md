# src-one 联动方案（蓝本溯源与 2026 重写定案）

> 定稿日期：2026-10-29
> 状态：方案定稿，实施随 ugoshop_reset 仓库 rebuild 分支批次推进；本文件随 memorial 分支滚动追加实施纪要（见文末）。

## 一、定位

本仓库（ugoshop 后台管理系统，2018.11-12）在 2026.10 评估后定案：**不复活原代码**（原样复活的评估结论为"可行但缺 MySQL 环境与数据"，价值有限），而是作为**需求蓝本**，在 ugoshop_reset（rebuild 分支）以现代栈重写为 admin 管理端，与 Vue3 重构的前台六页共用同一份数据库，实现 2018 年项目的完整闭环在 2026 新栈上复活：

**后台改商品 → 前台列表/详情/首页楼层实时变**

本仓库在联动中的角色 = 功能蓝本 + 考古档案。admin 的模块划分、字段、操作均以当年实现为蓝本，但代码一行不搬。

## 二、血缘证据（契约同源，非巧合）

ugoshop_reset 的 `server/src/db/schema.ts` 注释自证了数据血缘——rebuild 的四张表本就是从老 MySQL 契约映射而来：

| rebuild 表 | 血缘注释原文（摘） |
|------------|--------------------|
| `products` | "字段映射自原 mock-api.js 的 **ulist 契约**（doc/products.json 为底稿）：SID→sid, SNAME→name, STAG→brand, PRICE→price, SCON→description, URL→legacyUrl" |
| `users` | "字段映射自原 **f_user 契约**：fid→id、fname→username、fpws→password" |
| `cart` | "字段映射自原 **car 契约**：fid→user_id（改存 users.id）、sid→sid、sum→quantity" |
| `categories` | 数据原样取自 museum 的 newMenu.js（2019-07-26），对应老 `classify` 一级分类 |

而 mock-api.js 的契约又源自当年 MySQL `ulist` 表。即：**src-one 后台（直连 MySQL 四表）与 rebuild server（Drizzle 四表）是同一条数据血缘的两端，中间从未断链。**

## 三、蓝本映射表（2018 模块 → 2026 admin）

| 2018 模块（本仓库） | 老接口 / 文件 | 2026 admin（rebuild 分支） |
|---------------------|----------------|-----------------------------|
| 登录（index.html + idcode 图形验证码） | `POST /login`（router/login.js，查 f_user 明文） | `POST /api/admin/login`：users 表 `role='admin'`，scrypt 校验，独立 `admin_session` 签名 cookie（与 C 端会话隔离；图形验证码不沿用） |
| 商品列表 | `GET /goods`（LayUI table，分页） | `GET /api/admin/products`（Drizzle 参数化，真 count） |
| 商品新增 / 编辑 | `GET /goods/insert`、`/goods/update` | `POST /api/admin/products`、`PUT /api/admin/products/:sid` |
| 上下架 | `GET /goods/updown`（DIAN=1 上架 / 2 下架） | `PATCH /api/admin/products/:sid/status`（products.status，1/0） |
| 商品删除 | `DELETE /goods?id=SID`（三表共用一接口分发） | `DELETE /api/admin/products/:sid`（各资源独立接口） |
| 分类管理 | `GET /goods/classify(+add/amend)`，扁平一级 | `/api/admin/categories`：两级（categories + category_items，对齐前台两级菜单） |
| 用户管理 | `GET /user(+add/amend)`，f_user 增改 | `/api/admin/users`：列表 / 删除 / 重置密码（scrypt） |
| 订单管理 | `GET /car`（car 表；carcar.js） | `GET /api/admin/orders`：数据源 cart 表，**菜单名保留"订单管理"、注释留档当年购物车即订单的历史语义** |
| 图片上传 | `POST /goods/upload`（multer 只落盘不入库） | 批次 4：`/api/admin/upload`（入库 image 字段 + 静态托管） |

## 四、字段错位与接骨（schema 增列清单）

| 2018 字段 | 语义 | rebuild 现状 | 2026 接法 |
|-----------|------|--------------|-----------|
| `ulist.DIAN` | 上下架（1/2） | products 无此列 | 加 `status`（1 上架 / 0 下架，默认 1） |
| `ulist.REPE` | 数值字段，语义不可考（疑库存） | products 无此列 | 加 `stock`，语义按库存使用 |
| `ulist.URL` | 商品图路径 | 已换代为 `legacyUrl`（存档）+ `image`（AI 新图，前台全链路生效） | admin 编辑 `image`，legacyUrl 只读 |
| `classify` | 扁平一级（qid/qname） | categories + category_items 两级 + icon + sort | admin 分类管理对齐两级结构 |
| `f_user` 明文密码 / status | 明文比对登录 | users 表 scrypt（salt:hash） | admin 登录走 scrypt；users 加 `role` 列（admin/user），管理员由种子脚本创建——当年 f_user 本就同时管前台用户与后台登录，加 role 等于回归原点 |
| `car.cid` | 订单 ID | cart 表自增 id | 语义对应，无需处理 |

**C 端联动点**：rebuild 的 `GET /api/products` 列表/单查加 `status=1` 过滤——后台下架后前台列表消失、详情 404，前台六页纪念成果**零改动**。

## 五、当年代码缺陷考古清单（2026 重写逐项修正并留档）

| 位置 | 2018 写法 | 问题 | 2026 处置 |
|------|-----------|------|-----------|
| `router/login.js` | ``WHERE fname='${username}'AND fpws='${password}'`` | SQL 字符串拼接（注入）+ 明文密码 | Drizzle 参数化查询 + scrypt 哈希 |
| `router/goods.js` `/insert` `/update` | `async (res,req)=>{...res.query...req.send}` | 形参顺序反写，负负得正侥幸可跑 | 正常 `(request, reply)` 签名 |
| `router/user.js` | `"count": dataArr1.length` | 返回当前页条数当总数，分页失真 | `count()` 真实总数 |
| `router/goods.js` upload | multer 存盘后仅返回成功，注释"存储到数据库"未实现 | 图片与商品数据断链 | 上传后写入 products.image |
| `router/goods.js` DELETE | 单接口按 `id` 参数分发删 ulist/classify/f_user 三表 | 越权面大、语义混杂 | 各资源独立接口 + requireAdmin 统一守卫 |
| `router/car.js` | `sql2`（关联用户名查询）查完未使用 | 死代码 | 需要时再查，不预留死代码 |
| 登录页 index.html | idcode 前端图形验证码 | 纯前端校验无安全价值 | 移除，注释留档 |

## 六、联动批次（在 ugoshop_reset · rebuild 分支实施）

| 批次 | 内容 | 验收 |
|------|------|------|
| 1 骨架 | schema 三列（products.status/stock、users.role）+ 管理员种子 + admin 包脚手架（Element Plus，与前台同栈）+ 登录/登出闭环 | 能登录进管理壳；C 端会话进 admin 被正确 401 |
| 2 核心联动 | 商品 CRUD + 上下架 + C 端 status 过滤 | 后台下架/改价 → 前台列表、详情即时变 |
| 3 其余模块 | 分类两级管理、用户管理、订单（购物车）查看 | 全模块可操作 |
| 4 收尾 | 图片上传（含静态托管）、doc 更新、截图存档 | 部署级闭环 |

原则：admin 单一事实源在 ugoshop_reset，本仓库不双推代码；master 永久冻结，新增内容一律走 memorial 分支。
